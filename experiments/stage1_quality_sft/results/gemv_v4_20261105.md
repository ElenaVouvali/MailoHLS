# Stage-1 V4 GEMV inference — 5 November 2026

This is a genuine inference-only run through the existing production constrained
decoder, using the two final-root Stage-1 V4 latency adapters. It is a new
32×32 GEMV example, not a reproduction of the six Kalman outputs. No HLS
synthesis, measured QoR, test labels, or checkpoint selection was performed.

## Matched requests and legality

Both adapters received the identical two-request JSONL, with source from the
commit-pinned [GEMV input](https://github.com/ElenaVouvali/MailoHLS/blob/aa6ad1a20239250fc9236a3e87b35b1df99e6ca9/paper_figures/gemv_rc3_20261105/inputs/gemv.c), the corresponding authenticated action metadata, objective `PARETO_LATENCY`, 10 ns specified clock, and full device resource budgets.

| Request | Device | Clock | Budget |
|---|---|---:|---:|
| `gemv-zcu104-10ns-full` | ZCU104 (`xczu7ev-ffvc1156-2-e`) | 10 ns | 100% |
| `gemv-u200-10ns-full` | U200 (`xcu200-fsgd2104-2-e`) | 10 ns | 100% |

GEMV is absent from each adapter's saved directive-domain registry. The decoder
verified that registry's original SHA-256 against its training contract, then
used its existing missing-evaluation-kernel path to derive the GEMV domains from
the source and `kernel_info.txt`. That extension remained in process memory; the
saved registry was not edited. No measurements were read. All four predictions
have the exact five registered action IDs (`L1`–`L5`), all **13** required
directive fields, and values inside the source-derived domains.

## Generated directive comparison

Loop entries are `(PIPE, UNROLL)`; array entries are `(partition type, factor,
dimension)`. The assignments are identical across the two target requests for
each adapter in this controlled device comparison.

| Action | Single-reference (both devices) | Near-optimal multi-reference (both devices) |
|---|---|---|
| `L1` — array `A` | `(block, 4, 1)` | `(block, 2, 1)` |
| `L2` — array `x` | `(cyclic, 4, 1)` | `(cyclic, 2, 1)` |
| `L3` — array `y` | `(complete, 0, 1)` | `(cyclic, 4, 1)` |
| `L4` — outer loop | `(0, 2)` | `(0, 2)` |
| `L5` — inner loop | `(0, 4)` | `(0, 2)` |

So there are **zero changed directive fields between ZCU104 and U200 within
either adapter** for this pair of requests. The adapters differ from each other
on some array choices and `L5` unroll. This is descriptive output for one source
and one clock/budget setting, not evidence of target preference learning or
multi-reference superiority. The logged sequence scores are model log-score
summaries; they are not QoR scores.

## Reproduction and authentication

The [request file](gemv_v4_20261105_requests.jsonl) contains the full source and
both request records. The [machine-readable report](gemv_v4_20261105_report.json)
records each output's SHA-256, per-request prompt length and sequence score,
source/action/metadata identities, saved checkpoint and tokenizer hashes,
backbone revision, decoder settings, GPU preflight, and validation outcome.
Full [single-reference JSON](gemv_v4_20261105_single_reference.json) and
[JSONL](gemv_v4_20261105_single_reference.jsonl), and full
[multi-reference JSON](gemv_v4_20261105_multi_reference.json) and
[JSONL](gemv_v4_20261105_multi_reference.jsonl), retain the exact generated
strings and per-case request identity.

The run used `LLM_branch.inference.eval_stage1_stage2_stage3` with `--stage
stage1`, `num_samples=1`, deterministic greedy decoding, mean score reduction,
the production default candidate-prefix limits, and the existing 4-bit NF4
double-quantized backbone loader (FP16 compute on V100S). Both passes used the
same authenticated prompt schema, source/action metadata, saved domain
registry, request file, and pinned `deepseek-ai/deepseek-coder-6.7b-base`
revision `ce2207a8bfef3ee92bd7dd4cc31c52cfa0046912`. The assigned V100S
(`GPU-cea3d9e4-d189-a5b9-cf2e-9bd77b8218fb`) showed 1 MiB used, 0% utilization,
and no compute processes before each adapter pass. A2 was not used.

No generated assignment was compiled or synthesized. Resource feasibility is
unknown. The embeddings and GNN diagram in the other research branch are separate
evidence and did not enter this Stage-1 inference.
