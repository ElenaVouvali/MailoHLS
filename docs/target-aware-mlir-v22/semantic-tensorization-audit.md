# V2.2 semantic tensorization audit

Audit baseline: `research/v22-action-hardware-demand` at
`7c231f4b60871b91421ecaeb8683873fd1861c61`, schema
`salt-hls-mlir-structural-v2.2`, semantic revision `rc3`, and the authenticated
63-snapshot release listed in `docs/graph-release-v22-rc3.json`. This is an
inventory of tensor consumption, not an alteration of compiler facts.

| Compiler field / relation | Origin and overlay behavior | Current tensor / action-demand use | Evidence and relevance | Planned tensor representation; overlap |
|---|---|---|---|---|
| `memory_access.access_indices` (`affine_map`, `ssa_operands`, `operand_positions`, `induction_loops`, `status`) | Native V2.2 memory-access edge; retained verbatim by target overlay. | Edge has read/write and evidence indicators, but not affine map or SSA-to-map-input binding. Action-demand summarizes affine access counts; its restricted parser is used for candidate banking only. | Compiler-recorded or not-established. Access/index structure matters for partitioning and parallel accesses. | Extend existing edge features: exact, bounded map shape/coefficients/offsets; mark input operand role/position on corresponding `operand` edges only when SSA and operand-position lists bind exactly. Action-demand counts remain separate. |
| `operand` edges (`legacy_evidence.position`, `role`) | V2.2 source value → consuming operation; unchanged in overlay. | Typed forward/reverse message exists; current edge attributes omit operand position and index-vs-nonindex role. | Compiler SSA use fact; indexing role derives only by matching `access_indices.ssa_operands` and `operand_positions`. | Add positional and index-role channels to existing edge attributes; never fabricate direct IV edges. |
| `depends_on` (`dependence_kind`, `evidence_status`, `loop_carried`) | Native dependence analysis; overlay preserves. Includes `carrying_loop`, `carrying_loop_status`, `distance_bounds`, `distance_exact`, `distance_components`, `dependence_depth`, analysis-limit witness. | Kind/evidence/basic carried flag are encoded. Distance, carrying-loop relationship and depth are not. Static action-demand counts observed RAW/WAR/WAW and possible/proven carried records, but no distance vector. | `proven`, `possible`, or not established; absent edge is not independence. Relevant to unroll/pipeline legality and recurrence reasoning. | Append bounded signed-distance features with masks, exact-vs-interval status, dependence depth, and structural carrying-loop classification; do not treat missing components as zero. Existing demand counts are not duplicated. |
| `references` / `view_mapping` | Compiler relation retains `operation_kind`, `offset_semantics`, offsets/sizes/strides, source/result ranks and shapes, operands and overlap status; overlay preserves. | Relation direction/type/evidence only; no view transform semantics. Action-demand includes view witnesses in array summaries but does not tensorize per-dimension transforms. | Static fields can be proven or dynamic/unknown. Relevant to address/index interpretation. `subview` and `reinterpret_cast` offsets have distinct semantics. | Add categorical view kind/offset semantics and bounded per-dimension offset/size/stride values with independent masks; dynamic sentinel, unknown and rank overflow stay explicit. No view-chain composition. |
| `resolves_to`, `alias` (`alias_kind`, evidence) and root-set completeness | Native roots/aliases and RC3 completeness witnesses; retained. | Evidence state, alias category and memory-access root-completeness pair are encoded. Literal IDs are audit-only. Static action-demand counts proven/possible/unestablished root relations and incomplete sets. | Proven root identity is distinct from possible alternatives and candidate-set completeness; `no_alias` remains in a separate negative-edge tensor. | Keep positive/negative separation; encode certainty and completeness independently, plus knownness. Do not infer overlap or a unique root from shared candidates. Counts are not duplicated. |
| `loop_carried` (`forwarding_role`, `state_kind`, `carrying_loop`, `evidence_origin`) | Native SSA forwarding relation; retained. | Relation type and generic evidence only. | Compiler-recorded categorical role (e.g. schema role) describes initial/update/result forwarding; useful for recurrence and loop-state flow. | Add a small schema-derived category and status/knownness channels to existing edge features; unknown category explicit. No SSA-name features. |
| `calls`, `actual_to_formal`, `returns_to` (`argument_index`, `call_operation`, call/binding evidence) | Native interprocedural evidence; retained. Shared helper graph nodes are not cloned per invocation. | Relation types and basic argument-position numeric feature are present; call-site identity, binding certainty and forwarding context are not fully distinguished. Action-demand preserves call-scoped witnesses in JSON, not neural features. | Proven/possible/unresolved bindings; caller-specific roots must not collapse to one proven root. Useful for identifying helper context while retaining call approximation. | Keep existing relations, enrich edge attrs with argument-role/index knownness, binding/call status, and compact through-call evidence. No literal call IDs and no context expansion. |
| Source types / lowered numerical types | Compiler nodes retain MLIR lowered types and source correspondence status; overlay preserves. | Coarse value kind and width are encoded. | Lowered width may not match hardware/source arithmetic exactly where correspondence is unestablished. | Preserve fidelity/status masks; do not use unsupported widths to infer exact resources. Not part of the new edge-semantic expansion. |

All planned additions are derived tensor attributes. The graph archive and target
overlay remain byte-for-byte unchanged. Static action-demand vectors remain
unchanged and candidate-dependent demand remains outside the static GNN input.
